# 商品评价管理链路收口设计

## 目标

让商品评价在 C 端和后台管理端的分页语义一致、输入边界稳定，并保持既有审核、回复和接口路径不变。

## 范围

- C 端商品评价分页在查询到空记录时仍返回数据库真实 `total`、页码和页大小。
- 后台评价分页允许服务层接收空查询对象，统一默认页码和页大小，页大小最大为 100，并清理关键字首尾空白。
- 为以上行为补充服务层回归测试；现有审核、隐藏和回复动作不改变状态语义。

## 设计

`ProductCommentServiceImpl.page` 已经由 MyBatis-Plus 返回完整分页元数据。空页不需要特殊返回：直接构造 `PageResult`，复用 `enrich` 对空列表的安全处理，即可保留真实总数。

`AdminCommentServiceImpl.page` 在入口将空查询对象替换为默认 `AdminCommentQueryDTO`，并对页码、页大小和关键字做规范化。后续检索、过滤和富化全部使用该规范化对象，避免空指针、超大分页和空白关键字参与查询。

## 错误处理与测试

- C 端空页不视为错误，返回空列表和真实分页元数据。
- 后台空查询不视为错误，默认查询第一页、每页 10 条。
- 负页码与非正页大小回退默认值；超大页大小截断为 100。
- 测试通过 Mockito 捕获传入 MyBatis-Plus 的 `IPage`，并验证空页的总数没有丢失。

## 非目标

- 不新增评价创建、删除、审核状态流转或数据库字段。
- 不修改前端路由、部署文件和用户当前工作区中的未提交改动。
